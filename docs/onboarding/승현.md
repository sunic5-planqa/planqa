# 승현님 온보딩

## 맡은 일

1. **타문서 검토 대상 적용** — 지금은 기획서 한 종류만 검토하는데, 다른 문서 종류도
   검토 에이전트로 넘길 수 있게 백엔드 라우팅을 손보는 작업.
2. **'오류 원문' 넘버링 오류 진단** — 검토 결과에 찍히는 위치(넘버링)가 실제로 잘못
   잡힌 건지, 아니면 LLM이 순서를 헷갈린(hallucination) 건지 원인을 확인하는 작업.

## 어디서 작업하나

1번은 이 레포(`planqa`)의 **`backend/`** (FastAPI) — `POST /documents/{id}/qa-jobs`가
검토 에이전트를 호출하는 지점입니다.

2번은 진단이 목적이라 코드를 고치기 전에 먼저 **`planqa-agent`** 레포의 검토 결과
(`review.json`의 위치/`location` 필드)를 들여다봐야 할 수도 있어요. 거기는 코드를 고칠
필요는 없고, 재현되는 사례를 찾아서 이슈로 남기는 정도면 충분합니다.

## 시작하기

```bash
git clone https://github.com/sunic5-planqa/planqa.git
cd planqa/backend
uv sync
cp .env.example .env   # ANTHROPIC_API_KEY, GEMINI_API_KEYS — 혜서/가영한테 받기
uv run uvicorn sunnic_backend.main:app --reload
```

## 작업 흐름 (5단계)

1. `dev`에서 브랜치 따기
   ```bash
   git checkout dev && git pull
   git checkout -b feature/seunghyun-cross-doc-review
   ```
2. 코드 작성 (2번 진단 작업은 코드 변경 없이 GitHub 이슈로 재현 사례만 남겨도 됩니다)
3. 커밋: `<category>: <설명>` 형식, 영어, 70자 이내
4. `git push origin feature/seunghyun-...` — 본인 브랜치로만
5. `dev`를 대상으로 PR — 템플릿 체크리스트 채우기 → 승인 기다렸다가 merge

## 코드 스타일 (짧게)

- docstring/줄별 주석 없이, "왜"만 필요할 때 주석
- 한 줄 120자 제한
- 자세한 건 레포 루트 `CLAUDE.md` 참고
