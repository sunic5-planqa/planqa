# 보미님 온보딩

## 맡은 일

1. **수정하기 버튼** — 원문에서 오류 위치를 클릭하면 오른쪽 패널에서 바로 수정할 수 있고,
   여러 위치가 얽힌 이슈(예: 정합성 오류로 3-2와 7-4가 걸림)면 클릭할 때마다 그 위치로
   스크롤이 이동하는 기능. UI/UX 설계부터 구현까지.
2. **수정안의 QA 통과 배지** — 수정한 내용이 QA를 통과했다는 걸 보여주는 배지 UI.

## 어디서 작업하나

이 레포(`planqa`)의 **`extension/`** 폴더 — Confluence 사이드패널 크롬 익스텐션(TS/Vite)입니다.
`backend/`는 안 건드립니다.

## 시작하기

```bash
git clone https://github.com/sunic5-planqa/planqa.git
cd planqa/extension
npm install
npm run dev   # HMR로 개발, chrome://extensions에서 dist 로드
```

API 키 같은 건 이 작업엔 필요 없을 가능성이 높지만, 필요하면 혜서(@pforu) 또는
가영(@kayo2e)한테 물어보세요.

## 작업 흐름 (5단계)

1. `dev`에서 브랜치 따기
   ```bash
   git checkout dev && git pull
   git checkout -b feature/bomi-edit-button      # 또는 feature/bomi-qa-badge
   ```
2. 코드 작성 (아래 스타일 참고)
3. 커밋: `feat: add scroll-to-location on click` 처럼 `<category>: <설명>` 형식, 영어, 70자 이내
4. `git push origin feature/bomi-edit-button` — 본인 브랜치로만 push (main/dev 직접 push는
   시스템이 막습니다, 신경 안 써도 돼요)
5. GitHub에서 `dev`를 대상으로 PR — 템플릿 체크리스트 채우기 → 리뷰어가 자동으로 붙음 →
   승인 기다렸다가 merge

## 코드 스타일 (짧게)

- docstring, 줄별 설명 주석 쓰지 않기 — 주석은 "왜 이렇게 했는지"만, 그것도 진짜 헷갈릴 때만
- 한 줄 120자 넘기지 않기
- 자세한 건 레포 루트 `CLAUDE.md` 참고
