# 은성님 온보딩

## 맡은 일

1. **팀룰 추가 기능** — 팀마다 자기 도메인 룰을 추가할 수 있게 하는 기능. 와이어프레임부터
   시작해서(어떤 내용을 입력받을지, 화면 흐름) 승인받은 뒤 실제 구현까지.
   - 참고: 이 기능의 백엔드/데이터 설계는 `planqa-agent` 레포의
     `services/review-agent/docs/adr/0001-team-rule-authoring.md`에 이미 설계돼 있어요.
     와이어프레임 짤 때 "사람이 자연어로 룰을 입력 → 시스템이 초안(카테고리/티어/예시)을
     만들어 보여줌 → 사람이 확인 후 확정" 흐름이라는 걸 참고하면 화면 구성이 쉬워집니다.
2. **넘버링 하모나이징** — 문서 안 넘버링 체계를 통일하는 작업 (정확한 범위는 혜서/가영과
   먼저 확인).

## 어디서 작업하나

이 레포(`planqa`)의 **`extension/`** 폴더가 메인입니다. 룰 데이터 구조를 이해하려면
`planqa-agent` 레포도 참고용으로 열어볼 수 있지만, 거기 코드를 직접 고칠 필요는 없어요.

## 시작하기

```bash
git clone https://github.com/sunic5-planqa/planqa.git
cd planqa/extension
npm install
npm run dev
```

## 작업 흐름 (5단계)

1. `dev`에서 브랜치 따기
   ```bash
   git checkout dev && git pull
   git checkout -b feature/eunseong-team-rule-wireframe   # 또는 feature/eunseong-numbering
   ```
2. 코드/와이어프레임 작업 (와이어프레임은 Figma 등 외부 툴 결과물을 PR 설명에 링크로 첨부)
3. 커밋: `<category>: <설명>` 형식, 영어, 70자 이내
4. `git push origin feature/eunseong-...` — 본인 브랜치로만
5. `dev`를 대상으로 PR — 템플릿 체크리스트 채우기 → 승인 기다렸다가 merge

## 코드 스타일 (짧게)

- docstring/줄별 주석 없이, "왜"만 필요할 때 주석
- 한 줄 120자 제한
- 자세한 건 레포 루트 `CLAUDE.md` 참고
